# 文字とUIの設計

現行のドラクエ（XI / ウォーク系）のUIを基準に、レトロ感を落として情報の整理を優先した設計です。

---

## 0. 設計判断の記録

### レトロ表現をどこまで落としたか

「レトロ感を緩和」といっても、背景の16-bit風イラストまで捨てると絵の資産がなくなります。
そこで **絵はそのまま、UIとタイポグラフィだけを現行世代へ寄せる** 方針を取りました。

| 要素 | 以前 | いま |
|---|---|---|
| 時刻の字形 | ドット格子を拡大（22×30グリッド） | 距離場から起こした滑らかなベクター字形 |
| 窓 | 黒地・白の直角枠2px | 角丸14pxの濃紺ガラス（α205）・金の細枠2px |
| バッテリー | 10分割のブロックゲージ | 角丸の棒1本＋数値 |
| 天候アイコン | ディザリングの8bitアイコン | アンチエイリアスの図形 |
| 足あとアイコン | 2pxモジュールのドット絵 | 円の組み合わせ |
| 配色 | 白・黒・原色 | 濃紺・金・白の3層 |

### 廃止したもの

- **モンスター字形（0〜9）と中ボス13体。** 実装して実機で見たうえで撤去しました。
  仕様と生成プロンプトはgit履歴に残っています（`git log --diff-filter=D -- docs/monster-digits.md`）。

## 1. 字形の作り方

Zepp OSは**フォントファイルを読み込めません**。数字は画像で持つしかない、という制約は変わりません。
変わったのは、その画像の作り方です。

以前はドット格子（`'0111111110'` のような行の配列）を整数倍に拡大していました。
この方式では**拡大率がそのままジャギーの粗さになる**ため、8bit機の見た目から離れられません。

いまは各文字を**中心線のポリライン**として持ち（`tools/glyph-paths.mjs`）、
描画側が各画素で「最も近い線までの距離」を測って本体・縁取り・影を塗り分けます
（`tools/render-glyph.mjs`）。距離は連続値なので、**出力サイズをいくつにしても輪郭は滑らか**です。

```
距離 d が
  d < 線幅/2                    → 本体（縦グラデーション）
  線幅/2 ≤ d < 線幅/2 + 縁取り幅 → 縁取り（暗色）
影は同じ距離場を (0, 3) ずらして先に描く
```

縁取りと影を**画像に焼き込んである**ので、どの背景の上でも輪郭が消えません。
これは背景10枚の明るさがばらつくこの文字盤では必須です。

### 字形を直したいとき

`tools/glyph-paths.mjs` の `GLYPH_STROKES` を編集して `npm run assets` を実行します。
座標は 0..1 の正方形（x は右、y は下）で、値は**線の中心**です。輪郭ではありません。

## 2. 画面構成

```
y=0    ┌──────────────────────────────────────┐
       │  背景（天候別・10枚）                  │
y=40   │  ╭────────────────────────────────╮  │
       │  │ ☀  7/24 FRI              24°  │  │  外の様子
y=98   │  ╰────────────────────────────────╯  │
       │                                      │
y=170  │           10 : 09  AM                │  ← 時刻
y=250  │                                      │
       │                                      │
y=322  │  ╭────────────────────────────────╮  │
       │  │ HP ▬▬▬▬▬▬▬▬▬▬▬▬▬▬▭▭▭    78%  │  │  自分の状態
       │  │ 👣 3,548     L 23°     H 30°   │  │
y=410  │  ╰────────────────────────────────╯  │
y=450  └──────────────────────────────────────┘
```

### 情報の分け方

以前は「上＝日付とバッテリー / 下＝気温3列と歩数」で、
**現在気温が最低・最高と横並び**になっていました。いま何度かを知りたいときに
3つの数字から選ぶ必要があり、読む順番が決まりません。

いまは意味で分けています。

- **上の板 = 外の様子。** 天候アイコン・日付・**現在気温**。現在気温はアイコンと同じ行に置き、
  「外はどうなっているか」を1行で読み切れるようにしました。
- **下の板 = 自分の状態。** HPと歩数。今日の気温幅（L / H）は参考値なので2段目へ落とします。

### 座標

```js
topPanel:    { x: 30, y: 40,  w: 330, h: 58 }
time:        { y: 170, digitW: 56, digitH: 80, colonW: 20, gap: 6 }
bottomPanel: { x: 30, y: 322, w: 330, h: 88 }
panelRadius: 14
```

上下の板は画面端から等距離（40px）。中央224pxを絵に空けています。

時刻が乗る帯（背景ローカル座標 y160–240 / x49–368）は、
`tools/normalize-background.mjs` が明るい画素の比率を検査します。
**時刻の `y` を変えたら、あちらの `TIME_BAND` も必ず合わせてください。**

## 3. 配色

意味を持つ色は温度とHPだけに絞っています。装飾色を足すほど背景の絵に負けます。

| 用途 | 値 | 意図 |
|---|---|---|
| 板の地 | `#08182C` α205 | 真っ黒だと背景から浮いて板が主役になる |
| 板の縁 | `#CDB87E` | 現行ドラクエのコマンドウィンドウの識別色。白枠より柔らかい |
| 値 | `#F2F5FA` | |
| ラベル | `#CDB87E` | 値と同じ白にすると読む順番が決まらない |
| HP 緑/黄/赤 | `#5CC27A` / `#E8C15A` / `#E8695A` | 50%超 / 21〜50% / 20%以下 |
| 最低気温 | `#86C8F0` | |
| 最高気温 | `#F0A45C` | |

## 4. 容量

Zeus CLIはビルド時に**同梱PNGをすべてTGAへ変換**します。TGAは非圧縮なので、
**画素数がそのまま容量**になります。

| アセット | 枚数 | 実機サイズ | TGA換算 |
|---|---|---|---|
| 背景 | 10 | 366×430 | 6.3 MB |
| 時刻の数字 | 12 | 56×80 | 0.21 MB |
| AOD・気温の数字 | 39 | 17〜40px | 0.06 MB |

背景10枚が支配的で、字形はすべて足しても誤差の範囲です。

## 5. プレビューと実機の差

`docs/preview-*.png` は `tools/generate-assets.mjs` が `watchface/layout.js` を読んで合成しています。
**数字・アイコン・板は実機と同じ座標・同じ画像**ですが、次の2点だけ実機と異なります。

- **日付・HP・歩数・L/Hのラベル**は、実機では**システムフォント**で描かれます。
  プレビューではビットマップ字形で近似しているため、字幅と滑らかさが一致しません。
  実機のほうが滑らかに出ます。
- **板の角丸**は、実機ではZepp OSの`radius`で描かれます。プレビューは距離場で近似しているため、
  角がわずかに滑らかです。
